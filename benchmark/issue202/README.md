## ブロック・使用量・費用

終了理由は603回が `stop`、3回が `content_filter: OTHER`。ブロックはローマ字106番、カタカナ89番・174番で、各空出力はCER 1として集計済み。ひらがなはブロック0件。ブロックとHTTP等のエラーは区別する。

606回で入力256,673・返却出力9,928・総数266,601トークン。使用量不明・内訳不明差分は0。参考費用は **$0.612626**（評価600件$0.605818、ウォームアップ6回$0.006808）。疎通9回$0.010212を加えると615回で **$0.622838**。

推論トークンの詳細は全件未返却。差分0だけから思考処理なしとは断定しない。金額は導入期Standardの有料枠換算で、税・割引・請求明細そのものではない。

## 目的

高性能な推論モデルがSumibiの漢字変換にどこまで有利か、精度向上が応答時間・費用に見合うかを評価する。

既存のAJIMEE-Bench JWTD_v2/v1の同じ200例・同じプロンプトを使い、ローマ字・ひらがな・カタカナを各200件計測する。ウォームアップ各2回を含め606リクエスト。事前に各方式1件とウォームアップの疎通確認（計9回）を行う。比較対象は保存済みGemini 3.8 / 3.6 Flash、3.5 Flash-Lite、GPT-6.1 Sol。

## 公式仕様と計測条件

2026-10-31確認:

- [モデル仕様](https://ai.google.dev/gemini-api/docs/models/gemini-4-argon)
- [最新仕様・移行時の注意点](https://ai.google.dev/gemini-api/docs/latest-model)
- [OpenAI互換API・推論設定の対応](https://ai.google.dev/gemini-api/docs/openai)
- [料金](https://ai.google.dev/gemini-api/docs/pricing#gemini-4-argon)

| 項目 | 設定 |
|---|---|
| モデル | `gemini-4-argon`（Stable） |
| 接続先 | `https://generativelanguage.googleapis.com/v1beta/openai/chat/completions` |
| 推論 | `reasoning_effort=low`（低遅延向けに明示） |
| temperature / top_p / top_k | 送信しない（公式資料で削除が推奨されている） |
| n | 1 |
| verbosity / service_tier | 送信しない。Batch・Flex・Priorityを明示選択しない通常の同期API |
| 出力トークン上限 | 既存の測定と同じく明示指定しない。費用上限を保証しない |
| タイムアウト | 既存クライアントの既定120秒。`SUMIBI_AI_TIMEOUT` の変更値も監査JSONの `timeout_seconds` に記録する |
| SDK自動再試行 | 0回 |
| キー | 同じシェルの `SUMIBI_AI_API_KEY` のみ |

公式ではlow / medium / highに対応し、lowは最小トークン・最低遅延向け。noneを仮定せずlowを使った。OpenAI互換APIでの受理と利用権限は疎通確認・全件計測で確認済み。実測のタイムアウト設定は120秒だった。

公式ガイドには複雑なプロンプトで長いタイムアウトを使う案内があるが、本件は短文のIME用途評価なので既存の120秒を維持する。タイムアウト時は途中結果を保存して停止し、原因・費用を確認してから対応する。無断で再送や待機上限の変更はしない。

比較対象の推論条件は3.8とGPT-6.1 Solがlow、3.6と3.5 Flash-Liteがminimal。temperature指定・日時・通信環境にも差があり、同時期・同条件の厳密な比較ではない。モデル変更のみで精度が上がるとは仮定しない。
