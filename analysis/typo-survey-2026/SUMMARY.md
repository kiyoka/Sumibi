## 主な発見

### 1. SKK入力の特徴的な誤り

**同音異義語の選択ミスが圧倒的に多い（全体の約40%）**

頻出例:
- 安定板 → 安定版（5回以上）
- 時前 → 自前（3回以上）
- 再起 → 再帰（3回以上）
- 見方 → 味方
- 供に → 共に

### 2. LLM入力の特徴的な誤り

**助詞の脱落と語句の重複が主な誤り（合わせて約54%）**

頻出例:
- 助詞の脱落: 文章を確認には→文章の確認には、アプリケーションおいて→アプリケーションにおいて
- 語句の重複: 小さい範囲を翻訳範囲を→小さい範囲を
- 語句の脱落: 選択す→選択する、文章の途中なる→文章の途中になる
- 漢字の誤変換: ひらなが→ひらがな、表準出力→標準出力

**重要な特徴**: 同音異義語の誤変換はほぼゼロ（LLMが文脈から正しい語を選択）

### 3. 時系列による誤字率の変化（_posts/のみ）

- **2010年後半（バッチ7）で大幅改善**: 0.17件/ファイル（最低）
- **2009年後半〜2010年前半（バッチ6）が最悪**: 0.52件/ファイル
- 全体的には0.3〜0.4件/ファイルで推移

### 4. SKK入力とLLM入力の本質的な違い

#### SKK入力の弱点:
- ✗ 同音異義語の選択を人間が行うため、誤選択が多発
- ✓ 文法的な誤りは少ない（人間が文を構成）

#### LLM変換の弱点:
- ✓ 同音異義語の誤りはほぼゼロ（文脈から判断）
- ✗ 助詞の脱落や語句の重複が発生（生成の不完全性）

## Issue #120への示唆

この調査結果から、**Issue #120で提案されている「確定済み文章の校正機能」は、以下の誤りの検出に特に有効**と考えられます:

### 最優先で検出すべき誤り

1. **同音異義語の誤変換** (40%) - SKK入力の最大の弱点
   - 例: 再起→再帰、安定板→安定版、時前→自前
   - LLMは文脈から正しい語を判断可能

2. **助詞の脱落・誤り** (14%) - SKKでもLLMでも発生
   - 例: 参考した→参考にした
   - 文法解析で検出可能

3. **タイプミス** (17%) - 入力速度優先の結果
   - 例: ときかく→とにかく、ななり→かなり
   - スペルチェックや類似語検索で検出可能

4. **語句の重複** (8%) - LLM生成でも発生
   - 例: そのの、ということという
   - 正規表現で容易に検出可能

### 校正機能の設計指針

1. **文脈理解型の校正**: 同音異義語の適切性を判断
2. **文法チェック**: 助詞の使い方や活用形の検証
3. **パターンマッチング**: 語句の重複や典型的なタイプミスの検出
4. **ユーザーフィードバック**: 誤検出を減らすための学習機能

### 期待される効果

- SKK入力の弱点（同音異義語）をLLMの強みで補完
- 人間の校正作業を大幅に削減
- ブログ記事の品質向上
